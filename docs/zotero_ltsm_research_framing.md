# Zotero / LTSM：顶会时序论文如何提出问题

整理日期：2026-10-22。范围为 Zotero `LTSM`（`NCUGMYCT`）及其 `Survey`、`TS paper` 子文件夹。三个文件夹合计 76 次条目出现、75 个不同 item key；按标题规范化后为 68 个题名。重复条目包括 TimeRadar、GTM、PatchTST、iTransformer、两份相同的综述及一篇慢思考预测论文。下文优先分析已核对会议版/馆藏全文的代表论文；**LTSM 文件夹不等于其中每篇都是顶会，也不等于每篇都研究异常检测**。本文分析论文原有的问题—机制—实验证据，未复现数值。

八位大写字符串是 Zotero item key；本文件中的“启发”是面向 UAV 遥测的**研究假设推演**，不是该论文已经在 UAV 上证明的结论。会议版本优先于同一条目的 arXiv 元数据。

## 1. 总体观察：他们先改变什么

| 思考动作 | 代表论文 | 问题是怎样从现象收窄的 | 真正改变的对象 |
| --- | --- | --- | --- |
| 改变建模基本单位 | PatchTST、iTransformer | 时间点 token 太碎或把异质变量过早混合 | patch token；从时间 token 反转为变量 token |
| 根据时序性质重写算子 | Autoformer、TimesNet、TimeMixer、TimeMixer++ | 趋势/周期/尺度的结构不适合普通注意力或单一分辨率 | 分解、周期折叠、跨尺度传递的计算规则 |
| 区分变量的任务角色 | TimeXer、Moirai | 目标、外生量和可变数目的协变量不能一律同等对待 | 内生/外生 token 与跨变量交互；任意变量数编码 |
| 改变训练目标以适配任务 | MOMENT、Timer、TimesBERT、TimeRadar | 预训练语料/目标决定学到的是预测性、理解性还是异常可分性 | 掩码表征、自回归生成、局部偏离或时频旋转 |
| 改变默认数据假设 | TSAD-C、TimeMAE | “训练数据纯正常”“mask token 不影响下游”在现实中不成立 | 训练污染处理；可见/被遮蔽区域分离 |
| 改变能验证的实验场景 | Timer-XL、Time-MoE、MOMENT | 短窗口小数据集会掩盖长上下文、参数规模和数据稀缺问题 | 长上下文基准、规模曲线、少样本/零样本协议 |

关键不是在引言里写“依赖复杂、模型不足”，而是补上一句**可证伪的中间命题**：如果失败确实由 token 粒度、变量角色或预训练目标造成，那么只改变这一点，在相同骨干和数据条件下就应稳定改善相应场景。

## 2. 六种值得学习的问题提法

### 2.1 从表示单位入手：PatchTST 与 iTransformer

**PatchTST**（`J2SJ7HHQ`，ICLR 2023，[会议版](https://openreview.net/forum?id=Jbdc0vTOcol)）提出时间点作为 token 使注意力昂贵，且单点语义弱。其核心是把邻近时间点变成 patch，同时在共享权重下独立编码每个通道。论文用八个预测数据集、不同预测长度、patch 与 channel independence 的二因素消融、内存/时间比较支撑两项设计。它**没有**证明通道永远应独立，更没有证明 UAV 异常点能被 patch 保留。

**iTransformer**（`Z74BQLQQ`，ICLR 2024，[会议版](https://openreview.net/forum?id=JePfAI8fah)）反过来质疑多变量在同一时间戳被先压成一个 token：不同变量有不同单位和延迟关系。它把整段单变量轨迹作为变量 token，让注意力建模变量间关系、前馈层处理每变量的时间表征；数据集、长度、变量数分析与替换/移除组件实验对准这一轴变换。**看似与 PatchTST 的通道独立相反，其实两个假设适用条件不同**：问题应该被写成“哪种变量关系在何时值得显式建模”，而非选择一个当前流行的 tokenization。

对 UAV 的启发：先检查故障是否主要表现为单传感器局部形状，还是控制—响应、惯导—姿态的跨变量条件失配。需要两个公平对照：同骨干的 patch 独立编码与变量交互编码；在弱故障和正常机动中分别比较，不能只报平均预测 MSE。

### 2.2 从可观察的物理/统计结构入手：Autoformer → TimesNet → TimeMixer

**Autoformer**（`AS6Q3NIR`，NeurIPS 2021，[会议版](https://proceedings.neurips.cc/paper/2021/hash/bcc0d400288793e8bdcd7c19a8ac0c2b-Abstract.html)）从长时预测中的趋势与季节项出发，把分解嵌入模型，并用基于时延的 Auto-Correlation 替代普通点对点注意力；六个真实预测数据集和不同 horizon 验证设计。问题提法的优势是先解释“为什么注意力的匹配单位不对”，不是先说 Transformer 太慢。

**TimesNet**（`PI6L7MMT`，ICLR 2023，[会议版](https://openreview.net/forum?id=ju_Uqw384Oq)）观察到多周期使一维变化难表示：按候选周期把序列折成二维，把周期内与周期间变化放到两条轴。论文覆盖长/短预测、插补、分类及异常检测，验证的是这个**表示变换**的跨任务潜力；它的通用异常检测指标不能直接推论飞行故障时的误报和报警延迟。

**TimeMixer**（`SFV3KRIG`，ICLR 2024，馆藏 PDF 首页面注明会议版）认为微观与宏观变化位于不同尺度，因此季节项细到粗、趋势项粗到细地传递，未来预测再聚合多尺度结果。18 个真实预测基准、15 个基线和 PDM/FMM 的去除实验支持“跨尺度传递方向”而非仅仅“多尺度输入”。**TimeMixer++**（`DKAIMVGM`，ICLR 2025，馆藏 PDF 首页面注明会议版）进一步结合多尺度与多周期二维 time image，在八类任务含异常检测中做组件消融；但结构部件多，单次消融说明边际效益，未必证明各部件之间存在不可替代的协同。

对 UAV 的启发：若宣称“机动与故障的时标不同”，必须先画出按状态/故障类型分层的持续时间和频谱证据，再定义对应尺度如何交互。TimesNet、TSAE-UAV、TimeMixer++ 已占据周期折叠和多尺度路线，直接把其模块接在自编码器上没有新问题。

### 2.3 从变量角色入手：TimeXer

**TimeXer**（`M4QTRR8U`，NeurIPS 2024，[会议版](https://proceedings.neurips.cc/paper_files/paper/2024/hash/0113ef4642264adc2e6924a3cbbdf532-Abstract-Conference.html)）不再把多变量预测理解为“所有通道对称”，而是显式区分预测目标（内生）与已知外部量（外生）。目标历史被 patch 化，外生变量作为变量级 token，并以跨注意力及目标全局 token 传递信息。论文在带外生变量的短期预测与多变量长期预测场景比较，并消融 token 和外生输入。真正的问题是**任务中哪些变量有资格在预测时被观察**，不是多加一支 attention。

在 UAV 中，飞控命令、飞行状态、原始传感器、故障标签不对称。控制输入虽可观测，但其值受闭环反馈影响；把它称为“外生干预”会过度宣称。任何命令条件化预测必须明确控制/传感器的时间戳、预测时点可用性以及去掉命令后是否退化。

### 2.4 从预训练目标与实际任务错位入手：Timer、MOMENT、TimeRadar

**MOMENT**（`GCYRCSUY`，ICML 2024，[会议版](https://proceedings.mlr.press/v235/goswami24a.html)）先指出多领域时序缺大而整洁的公共预训练库及统一评测，再建立 Time Series Pile，用掩码表征支持预测、插补、分类和异常检测；强调少标注、少算力的迁移。**Timer**（`Q8EDKT29`，ICML 2024，[会议版](https://proceedings.mlr.press/v235/liu24cb.html)）从场景专用小模型的样本效率瓶颈出发，把异质数据化成单序列格式，采用 GPT 式生成目标，并把预测、插补、异常检测写到统一生成框架。两者是两种不同的**目标函数选择**，不能只比较参数量。

**Moirai**（`KG5SSNG6`，ICML 2024，[会议版](https://proceedings.mlr.press/v235/woo24a.html)）把通用预测需要的跨采样频率、任意变量数和分布差异列成具体约束，再设计多 patch 尺寸与 any-variate attention；训练语料和跨域预测/模块消融与问题逐项对应。**Time-MoE**（`TD7EBBJG`，ICLR 2025，馆藏会议 PDF）进一步把大容量与推理成本的矛盾具体化为稀疏激活专家，并给规模、速度和去专家消融。它们的预测优势不自动产生异常可分性。

**TimeRadar**（`UNECXKHZ`，KDD 2026，[会议版](https://doi.org/10.1145/3770855.3818062)）正是对这一迁移假设的挑战：为常见规律优化的预测表征，面对稀有异常可能无法拉开距离。其可学习分数阶时频旋转用于重构，再加入局部上下文偏离；以大规模预训练、未见 TSAD 数据集和“固定时域/频域 vs 可旋转域”等消融检验命题。**它解决的是异常检测目标与表征域的关系，而非单纯引入一个新变换。**馆藏也有同题 arXiv 条目 `XK5HKFKA`，不计作第二篇成果。

### 2.5 从被忽略的训练前提入手：TSAD-C

**TSAD-C**（`RELTK2KQ`，UAI 2025，[会议版](https://proceedings.mlr.press/v286/ho25a.html)）直接质疑很多无监督 AD 实验默认训练数据纯正常。它把训练异常混入视为核心问题，先去污染，再学习长程变量依赖，最后检测。论文对四个数据集比较，并让**污染率和训练中出现的异常类型数**变化，另去掉去污染器和其他组件。尽管由多个模块组成，其实验能单独检验“问题假设”是否重要；不能因为它有三阶段就概括成“拼接没有贡献”。但新论文若照搬去污染 + 图 + 扩散，也缺少新的任务机制。馆藏条目只有元数据，本节实验信息由正式会议全文核对。

UAV 的对应问题应从数据审计开始：所谓正常飞行中是否存在 GPS 丢失、起飞/降落过渡、传感器饱和等未标注扰动？若没有可重复的污染事实和不同污染率的实验，不应以“训练集不干净”作为套用去噪网络的理由。

### 2.6 从预训练—下游落差入手：TimesBERT、TimeMAE、TimeDART

**TimesBERT**（`JZUEYEMQ`，ACM MM 2025，[会议版](https://doi.org/10.1145/3746027.3755238)）把预测之外的分类、插补、异常检测称为时序理解，提出 masked patch 与 functional token 预测，以汇聚变量与多粒度特性；论文在多种理解任务和预训练组件上验证，但这不保证特定 UAV 弱故障一定可分。

**TimeMAE**（`43RZ4LYS`，WSDM 2026，[会议版](https://doi.org/10.1145/3773966.3778007)）指出逐点 mask 信息密度低且 mask token 使预训练/使用时编码路径不一致；把片段当语义单位，分离可见/被遮蔽区域的编码，结合离散码字和连续目标。主要实验证据是五个数据集的**少标签分类**，不是异常检测。**TimeDART**（`RCMZ7KY8`，ICML 2025，[会议版](https://proceedings.mlr.press/v267/wang25r.html)）用自回归因果编码加局部扩散去噪，论文消融 AR、DIFF，验证预测和分类；同样不能从“表征可迁移”直接推断异常分数有用。此处的思维方式是先找清训练目标和测试时任务之间的断裂，再设计对照，而不是默认“基础模型特征一定更好”。

## 4. 这些论文的实验证明链

1. **证明观察成立**：先显示哪个情形让已有做法失效。如 PatchTST 的 token 细碎和成本、TimeXer 的无外生信息、TSAD-C 的训练污染、TimeRadar 的固定域异常混叠。只有总体 SOTA 排名，没有分情形的失败证据，问题就太宽。
2. **证明核心结构，而非容量**：保持输入、参数、训练预算和阈值尽可能相同，单独改 token 轴、尺度传递方向、mask 处理或目标。PatchTST 的 patch/channel 双因素、iTransformer 的组件替换、TimeRadar 的固定时域/频域对照比“去掉模块”更有诊断性。
3. **证明问题特有的收益**：多尺度应在尺度变化大的状态上改善；异步输入应对不同采样率有收益；污染鲁棒性应画污染率/类型曲线；外生建模应分别展示有无命令及命令延迟。这是从叙事到可证伪假设的关键一步。
4. **证明代价与边界**：大模型应报告预训练语料、目标域重叠、显存/速度与少样本收益；在线检测应报告只能用过去信息、正常架次误报/小时、故障报警延迟和无 PA 指标。预测 MSE 或分类 accuracy 不能替代这些量。

## 5. 用于 UAV 异常检测的提问模板

> **观察**：在某类飞行状态/故障下，哪一种重构或预测基线出现系统性误报、漏报或过度重构？先给按完整架次分割的残差和案例。
>
> **原因假设**：错的是时间单位、变量角色、正常数据假设、目标函数，还是阈值/评价协议？每次只选一个首要原因。
>
> **结构推论**：如果该原因是真的，必须改变模型的哪个计算规则？为什么这个改变不能等价成“多一个分支再拼接”？
>
> **可观测预测**：收益应具体落在什么子集（机动切换、弱故障、传感器异采样、训练污染、未见机型），什么指标，什么代价？
>
> **反证实验**：相同骨干/预算/阈值下的替代结构，置乱或去除控制量，改变污染率和故障幅度；正常架次校准阈值，报告无 PA 的误报及延迟。

目前最值得先测而不是先设计大网络的两个问题是：**(a)** 控制命令和机体响应被当成对称通道输入后，正常机动是否造成异常分数上升；**(b)** “正常”训练架次中的未标注扰动是否导致 AE/预测器把异常学成正常。TimeXer 和 TSAD-C 提供了提问方法，**不等于把其网络移植到 UAV 就有新贡献**。下一步先做小规模基线/错误案例审计，再决定采用预测还是重构和需要改变的唯一核心机制；本次没有启动实验。
